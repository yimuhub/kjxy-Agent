## 1. 负责人为什么非用不可

### 1.1 他身上推不掉、必须交的三类活

| # | 必须交的活 | 现在系统的状态（证据） | 非用不可的条件 |
|---|---|---|---|
| 1 | **交材料**：对上汇报、项目结题、媒体报道、企业对接方案 | 只能出通用八段方案（`backend/app/modules/chat/plan.py:49`）；审查报告点名「没有'导出报告/周报'」（`docs/audit-report-2026-10-25.md:236`） | 材料里每个数字都必须来自系统台账；手写过不出来 |
| 2 | **交销量 / 交活动**：观摩会、丰收节、研学、直播、企业开放日 | 零支持：无活动、无订单、无客户实体；14 个内置 Agent 只是 persona + 提示词（`backend/app/modules/market/seeds.py:83`） | 活动只有在他手机里；进系统才能一键出方案+物料+复盘 |
| 3 | **交口碑**：咨询、投诉、差评、复购 | 工单只接设备告警（`farm/workorder_service.py:1`）；全仓 `grep 售后` **0 命中** | 不落库就统计不出首响与问题分布，周报与整改清单无从谈起 |

**结论**：不用这系统他也能用别的 AI 写文案；差别是——**别的 AI 没有这一院的产量、地块、活动、订单、投诉数据**。所以本批不做"更多技能"，做的是把三类必须交的活变成**只有本系统十分钟能出可交版本**，并把数据主键收进系统。与既有定位一致：「小院的知识与作业操作系统，而不是农业版 Dify」（`docs/state-report-2026-10-28.md:145`）。

### 1.2 外部证据（行业短板 + 合规硬约束 + 平台现实）

- 小院可持续压力：「可持续机制欠缺，存在'空心化'风险…高度依赖创始专家个人热情与阶段性科研项目经费」（新华社 2026-02-10）；地方把「品牌打造、电商销售等增值服务」列为成果转化方向（海南自贸港发布会）。
- 售后是行业公认短板：满意度研究中**「售后服务响应」均值最低（2.78）**，并把「售后缺失」列为核心痛点；行业侧描述生鲜直播「损耗高、售后退货多、供应链长、库存波动大」。
- 广告合规是硬约束：《广告法》第九条第三项禁止「国家级/最高级/最佳」等绝对化用语，市场监管总局《广告绝对化用语执法指南》（2023-02-25）明确范围与例外。
- **平台接口现实（决定"拿来就用"能做到什么程度）**：
  - 淘宝「商家后台系统应用」入驻要求**公司身份（支付宝企业认证）**，且**仅限天猫卖家**，「淘宝集市卖家不支持接入，推荐在服务市场订购相关应用」（淘宝开放平台文档）。→ 小院/合作社的集市店铺**拿不到自研接口**。
  - 拼多多「商家自研系统入驻」要求店铺已审核通过、**缴纳足额保证金**、已由招商小二对接并完成报备，应用审核 T+2、30 天内上线（拼多多开放平台文档）。→ 技术上可行，但要商家自己走完店铺侧流程。
  - 飞猪/携程：飞猪开放平台需**非个人店铺账号**登录入驻；携程商家侧多为合作签约类接口。
  - 文生图：阿里云百炼提供 Qwen-Image（擅长复杂文本渲染）与万相 wan2.6-t2i；豆包 Seedream 全量上线即梦/豆包；Nano-Banana（gemini-2.5-flash-image）提供 OpenAI 兼容的 images 接口。→ 可做统一 `image_generation` 能力，协议分「OpenAI 兼容 images」与「DashScope 原生」两类。

> 因此本方案对连接器的口径是：**内置的是"连接器模板 + 授权向导 + 降级路径"，不是"填个号就能拉单"**。免授权可用的是表格导入与 Webhook；直连需该店铺自己完成平台授权；淘宝集市按现实只能走表格导入或第三方聚合服务商（聚水潭/旺店通等）的开放接口。

### 4.3 订单/客户数据：**表格导入为主**（负责人拍板），直连仅作可选补充

统一抽象：`kind(import|webhook|api) + 字段映射 + 幂等键 + 批次报告`。**主力路径是表格导入**：内置各平台"订单导出模板"，上传 → 字段映射 → 预览差异 → 确认入库 → 出批次报告（成功/重复/失败行数 + 可下载错误清单）。同一份文件重传按幂等键去重，不产生重复台账。

| 档 | 覆盖平台 | 定位 | 路径 |
|---|---|---|---|
| **① 表格导入（主路，开箱可用）** | 淘宝/天猫、京东、拼多多、抖店、快手、小红书、携程、飞猪、美团，以及自建商城/合作社自记 | 所有平台统一入口，不依赖任何平台授权 | 下载/整理导出文件 → 上传 → 映射 → 预览 → 入库 → 批次报告 |
| **② Webhook 接单（可选）** | 自建商城、第三方中台、脚本 | 有技术能力的小院自推订单 | 配 URL + 签名密钥，按事件入库 |
| **③ 平台直连（可选，需商家自行授权）** | 拼多多、抖店、京东、有赞/微店（**不含淘宝/天猫/携程/飞猪**） | 仅当该店铺已有开发者应用且拿到授权时启用；**默认关闭** | 填 AppKey/AppSecret → OAuth → 测试 → 定时增量 |

**明确不做**：不对接淘宝聚合服务商（聚水潭/旺店通等），不为淘宝集市店铺做任何"绕过官方准入"的接入。淘宝/天猫/携程/飞猪一律走 ① 表格导入，连接器卡片上直接写明"官方不开放自研接入，请用导出模板"。

> 判断依据：淘宝「商家后台系统应用」要求公司身份且**仅限天猫卖家**，「淘宝集市卖家不支持接入」（淘宝开放平台文档）；拼多多商家自研需店铺审核通过、缴纳保证金、招商小二报备（拼多多开放平台文档）。表格导入不受这些门槛约束，是小院唯一稳定可用且最省事的路径。

### 4.4 客服/售后闭环与渠道

- 渠道注册表：**企微群 / 钉钉 / 飞书 / 站内对话**，全部纳入（入站通道 `bots` 已有企微 aibot/钉钉 Stream/飞书长连接，站内复用会话）。
- 入站分类：`咨询 | 售后 | 闲聊 | 需人工` → 前两类自动落 `growth_inquiry` / `WorkOrder(kind=after_sale)`；答案走 `cs_faq_answer`，**无证据一律转人工 + `cs_handoff`**。
- 出站：统一走 `push` 三通道（企微机器人/钉钉/webhook）；站内则回原会话。审批策略见 §5。
- 意图分流 `chat/intent.py` 增 5 类（campaign/inquiry/aftersale/ledger/material），**侧栏只净增 2 个入口**（「增长经营」「服务与工单」）——回应审查报告「17 个入口」（`audit-report:205`）。

### 4.5 海报：文生图 + 提示词工程（按拍板改）

三层，缺一层都不成：

1. **提示词转化（技能层）**：`growth_poster_prompt` 把自然语言变成"高产出"结构化提示词——主体、场景、风格（写实/国潮/清新/节庆）、构图与留白（给文字与二维码留位）、光线、色彩、尺寸比（1:1 / 3:4 / 9:16）、负面词、合规约束（不出现绝对化用语、不夸大成色与功效）。**风格预设库 + 模板可编辑**：小院可改字段、存自己的预设、按品类复用（这是你要的"灵活"）。
2. **生成通道（能力层）：一律走「模型中心 · 模型供应商」，完全自主可控**——不新开一套"图像服务"，而是把图像/视频模型注册成供应商：
   - 能力码新增 `image_generation`（本期）与 `video_generation`（预留，同一套通道），加入 `llm/capabilities.py` 的能力表（现有 22 条，`backend/app/modules/llm/capabilities.py:24-55` 中无图像/视频）；
   - 供应商增加**模型类型** `model_kind = chat | embedding | image | video` 与**协议适配器**：`openai_images`（OpenAI 兼容 `/v1/images/generations`，Nano-Banana 等）、`dashscope_image`（Qwen-Image / 万相 wan2.6-t2i，中文版式更稳）、`openai_video`（预留给视频）。协议差异只存在于 Provider 适配层，上层（绑定、熔断、计量、trace）全部复用 3.25 现有机制；
   - 取用方式与对话完全一致：`provider_resolution(purpose="image_generation")` → `binding_service.resolve_chain` 七档解析 → 命中供应商即出图；`/llm/bindings` 按能力绑定"出图用谁"，与对话模型**分开绑定、分开计费、分开熔断**（`llm_calls.purpose` 已入库，可直接按能力统计成本）；
   - 小院在**模型中心 → 供应商**里自己填 base_url / Key / 模型名（Key 走 Fernet 密文，编辑不回填明文），保存即生效、无需重启；谁能管理由 `llm:manage` 控制。
3. **套版合成（渲染层）**：出图后用 Pillow 叠加文案、价格、二维码、落款（文字先过 `growth_ad_compliance`）；保证"图是模型画的、字是确定的"，避免模型把中文写错。
4. **降级**：该小院尚未录入 `image` 类型供应商、或供应商停用/熔断 → 回落模板渲染并明确提示"当前为模板版"；**不静默降级**。

> 为什么不另做一套图像服务：你要求"完全自主可控"，那么图像/视频模型就应该和对话模型一样——由小院自己选供应商、自己配 Key、走同一条解析链与同一张用量表。这样换模型只改绑定，不用改代码；将来接视频也只是多一个 `video_generation` 能力码与一个协议适配器。

### 4.6 按 Agent 配模型：一个专门的配置入口（本次新增）

现状：3.25 已支持按智能体绑定（`frontend/src/components/settings/ModelBindings.vue:148` 的 `scope_type='agent'`，解析预览按 `agent_code` 取，`:184-190`），但入口藏在「模型中心 → 按智能体绑定」页签里；同时助手编辑页还留着「指定模型」单供应商选择，两处各配一半（`docs/plan-v3.24-permissions-model-tools.md` §9 未完事项已记录"两处尚未合并"）。本批做成"一个地方配完"：

- **新页面 模型中心 → 智能体模型**（独立页签）：列出全部可用助手（内置六角色 + 专业助手 + 已发布自建），每行显示继承来源（能力绑定/全局默认）、主用供应商与模型、兜底 2 档、"试跑"、最近一次调用结果；支持按名称搜索与"只看已自定义"筛选。
- **助手编辑页的「指定模型」改为三态**：跟随中心（默认）/ 指定模型 / 停用模型，与上面同一份数据（`llm_bindings`，`scope_type=agent`），保存即生效——消灭两套入口。
- **后端**：复用 `PUT /llm/bindings`（整层替换、顺序即兜底顺序）、`GET /llm/bindings/resolution?agent_code=`、`POST /llm/bindings/test`；新增聚合 `GET /llm/bindings/agents`（一次返回全部助手 + 当前绑定/继承来源/可用性），避免前端 N+1。
- **权限**：沿用 `llm:manage`；只读角色可看"它会用谁"、不可改。
- **验收**：改任一 Agent 的模型后，该 Agent 下一次调用即用新模型（以 trace 里的 `supplier_id` 为证），无需重启；被停用/熔断的供应商标"不可用（原因）"。
- 图像/视频也在这里：同一页面下方按 `image_generation` / `video_generation` 能力各给一档"默认用谁 + 兜底"，谁能出图/出视频一眼可见。

**2026-10-30 实现口径（D-1.5 已落地）**：三态收敛为「跟随中心 / 指定模型」两态 + 「旧设置（待接管）」提示；「停用模型」落地为**停用助手**（助手页发布/停用），因为平台内置助手没有按小院停用的承载表，硬造一张空表不如不造。保存智能体绑定会清空该自建助手的旧 `supplier_id/model_name`，从根上消灭两套入口互相覆盖。

### 4.7 权限点（新增 5 个）

`growth:manage`（活动/排期/台账写）、`growth:read`、`service:manage`（线索与售后处置）、**`service:reply`（对外回复与群发）**、**`growth:connect`（平台连接与凭证管理）**。后两个为**保护型**（仅负责人默认拥有，增减需二次确认，沿用 `permissions.py:75`）。
默认矩阵：负责人全集；小院管理员含 growth:*、service:manage 但**不含 service:reply / growth:connect**；操作员 growth:read + service:manage；普通成员只读。403 文案必须写清"找谁开通"（`audit-report:253`）。

### 4.8 审批策略：负责人可选的开关（按拍板改）

小院设置新增 `service.reply_policy`，三档，负责人自选、改动留痕（写审计）：

| 档 | 行为 | 适用 |
|---|---|---|
| **强制审批（默认）** | 所有对外回复进"待发送"，人点确认后才发 | 刚上手、口碑敏感期 |
| **仅承诺类审批** | 事实类（产地/规格/物流/储存）自动发；涉及补发/退款/赔偿/时限的一律等人批 | 日常最常用 |
| **全自动（带硬上限）** | 全部自动发，但**单笔补偿金额超过阈值 / 涉及食品安全投诉**强制转人工 | 客服量大、话术成熟后 |

无论哪档：外发前必过合规体检、自动发出的消息**留全文与依据**、可一键撤回提示、每日汇总推给负责人。

## 5. 合规与安全红线（不可让渡）

1. 广告合规：绝对化用语与不可举证宣称一律拦截并给改写（《广告法》第九条第三项 + 2023《广告绝对化用语执法指南》）。
2. 食品/农产品不做疗效、疾病治疗、"最健康"类宣称；产地/等级/有机必须引用库内证据，否则标"待核实"。
3. 对外承诺受 §4.7 策略约束；**食品安全与超阈值补偿永远人工**。
4. 连接器**只读同步**：不改单、不发货、不退款、不代客操作后台；任何写动作需人工在平台侧完成。
5. 不自动群发、不刷单、不诱导好评；个人微信直连继续不做（`plan-bot-gateway-v2.md:53`）。
6. 凭证 Fernet 加密、编辑不回填明文；顾客标识哈希；会话正文可见性沿用「负责人逐人授权」（`permissions.py:4-7`）。
7. 每个技能出厂 ≥2 条评测用例 + 静态检查 + Ed25519 签名，详情页可见"被测过、签名是谁"。

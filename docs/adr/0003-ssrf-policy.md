# ADR-0003：SSRF 出网校验的私有网段策略（安全与私有化兼容）

- 状态：已采纳
- 日期：2026-10-17
- 相关：五维测评报告 B 级发现“SSRF 防护零实现”（规范 §15.1）

## 背景

规范要求网页抓取/URL 导入防 SSRF：禁止访问本机、内网、云元数据地址。但科技小院的
核心交付形态包含内网私有化部署（模型服务、Embedding 服务常在内网主机），无条件禁止
RFC1918 会直接破坏合法部署。

## 决策

新增 `core/net_guard.check_egress_url()`，接入供应商探测、模型 chat、Embedding 出网点：

1. **始终阻断**：loopback、link-local（含 169.254.169.254 云元数据）、组播、保留、未指定地址；
2. **私有网段默认放行**（内网模型服务场景），`ENFORCE_MODEL_EGRESS_GUARD=true` 时一并阻断
   （纯公网 SaaS 部署应开启）；
3. DNS 解析失败放行给 HTTP 客户端自然失败（避免离线/单测误伤）；出网前解析全部 IP 逐一校验。

## 备选方案

- 一律禁止私有网段：破坏私有化形态，被否。
- URL allowlist：管理成本过高（供应商动态域名），列为后续增强。

## 收益 / 代价 / 风险

以最小侵入达成规范主要目标；残余风险：`enforce=false` 时管理员可让服务端访问内网
（这是特性所需），但元数据地址等高危面已封死；供应商配置入口本身有 admin 权限与 HTTPS
校验，并在响应错误码 `SSRF_BLOCKED` 中保持一致信封。日志记录私有网段放行的每次决策。

## 迁移/回滚

不改数据；如需回退删除调用点即可（不建议）。

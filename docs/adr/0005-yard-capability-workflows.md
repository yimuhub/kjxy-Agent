# ADR-0005：小院声明式 Agent 与能力分权审核（能力中心工作流的基础权限模型）

- 状态：已采纳（2026-10-18 产品决策）
- 相关：§5.2 RBAC、§8.1 Agent 定义、§11 自进化、ADR-0004（声明式工作流）、ADR-0002

## 背景

yard_admin 需要自助管理模型接入、Skill 与 Agent，且要求"一键/按行业自动生成"。
规范红线：模型生成物不得低于人工审核直接进入可用态（§0.2/§11）；但全部走 expert
人工复核会让小院侧效率归零，与产品目标冲突。

## 决策：按"风险×归属"分级，而非一刀切

| 创建者 | 产物 | 审核路径 |
|---|---|---|
| platform_admin | 任何 Agent/Skill | 直接发布（其本人即最高审核人，动作全量审计） |
| yard_admin | **本小院专属 + 低风险**：工具白名单仅含无副作用工具、limit 齐备、knowledge_scopes 非空、不含设备/工单/对外提交类能力 | 自批发布（`agent:manage` 权限 + 审计 + 版本化可回滚） |
| yard_admin | **高风险**（任一命中：含副作用工具、无知识范围限制、申请跨小院共享、请求更高权限点） | 自动打高风险标 → 进平台审核队列 → platform_admin 批准后才 published |

补充约束：
1. 自动生成的产物（工厂/LLM 生成）默认 `draft`，"发布"动作必须由人点击（自动产物的红线不因
   分级而放松——分级决定的是**谁来点**，不是**要不要点**）；
2. 工具白名单服务端硬校验（禁 `*`），风险判定函数是纯函数、可测试、宁严勿松；
3. 供应商密钥：小院级 Fernet 密文存储、永不回显（既有 suppliers 模块纪律），yard_admin
   仅管理 `yard_id=本小院` 的行，平台全局行只读可选用；
4. 外部检索（知识库不足时启用）产物一律 `model_candidate` 可信级 + 来源 URL，走既有
   knowledge 审核队列；默认关闭、小院显式开启、SSRF guard + 频控 + 官方源优先；
5. 高危拦截兜底沿用运行时：即便配置错误，R3 类副作用工具调用仍被运行时审批闸门拦截。

## 备选

- 全量 expert 审核：合规最稳但小院自助名存实亡，被否。
- 全量自动发布（仅平台级兜底）：违反 §11 红线，被否。

## 影响

新增权限点/队列：`agent:manage`（yard）、`platform_review_queue`（列表+批准/驳回，
platform_admin）、审计动作 `agent_created/published/pending_review/reviewed`。
迁移：新表 `yard_agents`（声明式定义版本化）、`factory_runs`（工厂蓝图快照）。

## 补充（2026-10-26，v2.0 助手私有化）：成员可自建"只能自己使用"的助手

原决策把"创建"整体归给 yard_admin（管理员执行/成员申请）。v2.0 的 @ 点名与群聊要求
成员能把自己的小助手拉进会话，因此按**可见性**重新分权，红线不变（发布仍由人点击、
高风险仍需审核）：

| 动作 | public 助手 | private 助手 |
|---|---|---|
| 创建 | 仅 yard_admin/platform_admin | 成员可建；成员显式请求 public → 403（不静默降级） |
| 编辑/复制/停用/删除/首图 | 仅管理员 | 管理员或**创建者本人**（`require_manage_access`） |
| 发布 | 管理员低风险自批；高风险进平台队列 | 管理员同上；**创建者本人仅限低风险**，高风险需管理员 |
| 可见/可路由/@ 候选 | 全院 | 仅创建者（`user_id` 缺失的系统路径 fail-closed 只认 public） |

理由：私有助手只有创建者能用，其风险面天然小于公开助手，但仍受同一套纯函数
`assess_risk` 约束——含副作用工具/无知识范围的私有助手照样判高风险，成员发不出去。
展示层的"原名（用户名私有）"后缀在服务层派生，不写进 `name` 列，因此同小院唯一名约束
（`uq_yard_agents_yard_name`）与 @ 列表都作用于干净名称。

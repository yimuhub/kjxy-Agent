# ADR-0001：首版采用模块化单体 + Docker Compose，而非微服务/K8s

- 状态：已采纳
- 日期：2026-10-16

## 背景

首版目标是快速交付可验证的农业业务闭环（问答+知识库+专家纠错+任务留痕），团队规模小，运维能力有限。

## 决策

后端为模块化单体（按领域划分 Python package，API 与 Worker 进程分离），部署用 Docker Compose；不在首版建设微服务集群或 Kubernetes。

## 备选方案

微服务拆分 + K8s 编排：被否决，首版运维负担过重，且模块边界可通过代码依赖与测试保证。

## 收益

开发/部署/排错简单；新开发者按 README 可独立启动；单机试点成本低。

## 代价

单机扩展上限；多实例部署时需外置会话/锁（已用 Redis）。

## 安全影响

无新增面；小院隔离在应用层实现，与部署形态无关。

## 迁移/回滚

后续若需拆分，按模块 package 边界逐步抽取为服务；API 契约（/api/v1）保持不变。

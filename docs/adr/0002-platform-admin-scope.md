# ADR-0002：platform_admin 权限范围——首版保留跨小院平台能力，内容访问收敛为"配置与运营元数据"

- 状态：已采纳（首版偏差记录，P1 收敛排期）
- 日期：2026-10-17

## 背景

规范 §1.2 与 §5.1 规定：平台管理员负责"小院、模型配置、系统状态和全局策略"，**不默认读取小院业务正文**。

当前实现为交付速度做了简化：`platform_admin` 角色持有 `ALL_PERMISSIONS` 且可跨小院行使（`yards/permissions.py`、`tools/approvals_router.py` 的 `_requester_roles` 将平台管理员注入任意小院角色集）。效果是：平台管理员事实上可以进入任意小院查看知识正文、任务结果与审批单内容——与 §1.2 的"运营权限与业务内容访问分离"存在偏差。

## 决策

1. **首版保留**平台管理员的跨小院**配置/运营**能力（小院管理、配额、供应商配置、健康与成本视图）——这是 SaaS 运营的现实需要，且试点期团队规模小，缺少独立运维角色。
2. **明确偏差**：平台管理员可以"看到"小院业务资源的存在性与状态（任务/文档/审批的元数据），**不以此作为产品能力承诺**；审计日志保留其全部操作记录（`log_audit` 已覆盖）。
3. **P1 收敛方案**（排期）：
   - 将 `platform_admin` 拆为 `platform_ops`（小院/配额/供应商/监控，不触业务正文）与 `platform_admin`（保留平台级配置与全局策略，仍不默认读业务正文）；
   - `knowledge/documents`、`tasks`、`tool-approvals` 的正文类接口对平台管理员返回**元数据视图**（状态、计数、耗时、成本），正文需小院管理员/专家授权；
   - 越权测试增加"平台管理员读取小院知识正文"负向用例（`tests/security/`）。

## 备选方案

- **首版立即收敛**：平台管理员完全不能跨小院——被否决：试点期没有专职运维角色，供应商配置/配额调整必须有人做，拆出运维角色反而增加管理成本。
- **维持现状不记录**：被否决：规范 §2.5 要求改变权限语义必须 ADR；沉默偏差是安全审计漏洞。

## 收益

试点期可运营（平台级配置有人管）；偏差显式化，后续收敛有目标与测试锚点。

## 代价

平台管理员账号泄露的影响面大于规范默认值；需要收敛迭代。

## 安全影响

- 缓解：平台管理员操作全量审计；密钥与业务正文在 API 层仍按小院过滤，平台管理员跨小院仅通过"平台级"路由（ yards / quotas / suppliers / llm status），不直接拼接小院正文查询。
- 残留风险：`_requester_roles` 将 platform_admin 注入小院角色集的路径，工具执行时按小院角色鉴权——收敛前保持该行为并在代码注释标注本 ADR。

## 迁移/回滚

收敛通过新增角色与接口视图切换完成，不改表结构；回滚即恢复 `ALL_PERMISSIONS` 映射。

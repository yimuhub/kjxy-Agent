# ADR-0006：订阅计费在支付网关前的自助闭环（v3.71）

日期：2026-11-07 · 状态：已接受

## 背景

五维度审查报告（docs/review-report-2026-11-07.html）将「支付/订单闭环」列为 P0：
官方模型通道已有订单、验签 webhook 与 entitlement 底座（v3.33），但微信/支付宝
网关需要商户资质与密钥才能接通，短期无法完成真实支付。客户当前无法自助开通/续费。

## 决策

新增 `billing` 模块（`/billing/*`），用两条**不依赖网关**的真实闭环先行：

1. **兑换码**：平台管理员线下收款后发码（`POST /billing/codes`），小院管理员在
   配额页输码兑换（`POST /billing/redeem`），订单直接进入已支付并即时写
   `quota_grants`。码值（KY-XXXX-XXXX-XXXX）即安全凭据，带 90 天默认有效期。
2. **对公转账订单**：小院选套餐下单并附转账凭证说明，平台管理员确认到账
   （`POST /billing/orders/{id}/confirm`）后自动到账。

两条路最终统一走 `_mark_paid_and_grant`：pending → paid + 按套餐目录逐项写
`QuotaGrant`（`granted_at` 幂等闸防重复到账），**不修改客户已配置的策略上限**，
超限语义不因购买改变。

## 理由

- 到账翻译成配额而非「开通功能」：配额体系（v3.32）已有作用域×指标×窗口建模，
  订阅/加油包只是追加额度的两种来源，复用最大、语义最清楚。
- 不伪造第三方支付成功状态（对齐「诚实占位」原则）；网关接入后 webhook 通道
  （官方模型已有验签实现）可平移复用同一 `_mark_paid_and_grant`。
- 权限不新增权限点：兑换/下单复用 `quota:manage`，发码/确认复用平台管理员闸
  （DB 复核），避免权限目录膨胀。

## 后果

- 新表 `billing_codes` / `billing_orders`（迁移 0076，downgrade 对称）。
- 套餐目录是代码常量（`billing/plans.py`），改价/增档需发版——刻意选择：
  档位是商务决策，不该让运行时数据悄悄漂移。
- 网关接入时只需新增「回调 → 找单 → mark_paid」一条路径。

# 科技小院中枢：角色群组工作台与权限延伸方案（2026-11-04）

> 目标：让小院 Agent 从「一个工具」变成「科技小院的中枢」——把负责人（教授/首席专家）、
> 驻点研究生、小院工作人员（技术员）、农户、学校研究生院五类人汇集到同一个平台，
> **每个人登录后看到的是自己的工作台，解决的是自己真正的问题**。
> 价值主张：台账/报告/培训材料/问诊响应这些「必须有人干的活」交给平台，
> 小院少雇一个全职文员 ≈ 每年省 5-8 万元；研究生省下填报时间做试验。

## 一、角色 × 痛点 × 平台能力矩阵（基于调研的真实制度）

| 角色 | 现实痛点（调研实证） | 平台该给他什么 | 现状差距 |
| --- | --- | --- | --- |
| **小院负责人**（教授/首席专家） | 要对学校/科协交年度评价；不驻点但要对结果负责；关心成本 | 驾驶舱：周报自动推送（✅已做）、月报导出（✅已做）、成本与人力节省量化、审批中心 | 缺「人力节省量化」与跨小院视图 |
| **驻点研究生** | **日志+月报填报挂钩毕业考核**（全国平台硬要求）；重复填报被点名整治；田间数据与日志脱节 | 日志工作台：从会话/任务/设备数据**自动汇总日志草稿**→人工确认→一键同步到全国平台口径；驻点天数/日志篇数进度条 | **缺（P0 灵魂项）** |
| **小院工作人员/技术员** | 塘口/大棚巡检、设备维护、农事记录全靠纸和人脑 | 移动端任务清单（bots 命令+待办）、设备告警直达、口述转台账（✅台账助手已做） | 缺任务分派闭环 |
| **农户** | 不会用软件；问题没人随时答；培训记不住 | 企微/钉钉扫码进群问（✅bots+/技能已做）；培训提醒推送；共享页看公开成果 | 基本已覆盖，缺「培训提醒」 |
| **学校研究生院/学院** | 多小院监管靠年底收表；日志核查（查重）是人工活 | 监管看板：全部小院的日志量/培训人次/推广技术聚合 + 异常预警（某院日志断更） | **缺（P1）** |

## 二、权限模型：从「角色门」到「角色工作台」

现有权限体系已经支持点级控制（角色默认 + 逐人 grants），**不需要推倒重来**，
做三件事：

### 2.1 角色与权限映射（现状校准，微调即可）

| 平台角色 | 对应小院身份 | 默认工作台 |
| --- | --- | --- |
| yard_owner | 小院负责人（首席专家常兼任） | 负责人驾驶舱 |
| yard_admin | 小院执行管理（驻点高年级研究生/技术员长） | 管理台（成员/审批/设置） |
| expert | 校内专家/导师（不驻点） | 专家问诊台 |
| operator | 驻点研究生/技术员 | **日志工作台**（新） |
| viewer | 农户/合作社会员 | 对话 + 公享页 |

新增权限点（进 `ALL_PERMISSIONS` + 角色默认矩阵）：
- `logs:write`（operator 默认有）：写/提交小院日志与月报；
- `logs:review`（yard_admin/owner/expert）：审核日志草稿；
- `yards:aggregate`（platform_admin 专属）：跨小院监管看板。

### 2.2 登录后落地页 = 角色工作台（前端一处路由守卫改动）

`/` 按角色跳转：owner→驾驶舱、expert→问诊台、operator→日志台、其余→对话。
菜单（menu.ts）本就按角色渲染，工作台即每个角色菜单的第一项。

### 2.3 数据边界沿用 yard_id 隔离

所有新表/查询沿用现有 `yard_id` JWT 隔离口径；跨小院只有 `yards:aggregate`
（platform_admin）能读聚合统计（且只出数字不出正文）。

## 三、功能设计（按角色）

### 3.1 研究生日志工作台（P0，灵魂项）

**为什么是灵魂**：日志/月报是全国平台的硬考核（研究生毕业相关），也是调研中
唯一「每家都在做且都在应付」的事。把它做好，研究生**每天都用**。

- **自动草稿**：研究生当天与小院的每一次对话、跑过的指挥官任务、设备告警处置、
  台账条目 → 按日聚合成「日志草稿」（今天做了什么/数据/下一步），人工增改确认；
  语气口径按全国平台要求（客观、可追溯、无评价性语言——复用台账助手 prompt）。
- **月报**：日志按月聚合成月报草稿（复用指挥官周报聚合管线）。
- **考核进度**：日志篇数/驻点天数/培训人次进度条（对照年度目标）。
- **导出**：日志/月报导出 Word（复用 A3 管线），贴进全国平台表单即可。
- 数据表：`yard_journal`（yard_id, author_user_id, date, kind=daily|monthly,
  content_md, sources_json, status=draft|submitted, reviewed_by/at）。

### 3.2 专家问诊台（P0，低成本）

expert 登录后的第一屏：待审技能/知识（✅已有）+ **各小院上报的问题聚合**
（feedback + 会话中「转专家」标记）+ 回复直达该小院对话（bots 群里农户直接收到）。
复用现有 feedback 模块与审计，无需新表。

### 3.3 学校监管看板（P1）

platform_admin：N 个小院的日志量/培训人次/技术推广条数聚合表 + 「日志断更 7 天」
预警列表。数据全部来自各小院已有统计（insights/journal），只做聚合视图。

### 3.4 农户培训提醒（P2）

bots 通道订阅 `training_reminder`：小院排了培训 → 农户群收到提醒卡片。
推送框架现成（push.dispatch）。

## 四、价值量化（给负责人看的话术，写进产品首页）

按调研数据（江苏 89 家、研究生 747 人、指导老师 825 人）：
- 每个研究生每天省 30 分钟填报整理 → 全省一年 ≈ **4500 人日**还给科研；
- 台账/汇报/培训材料自动化 → 每小院少雇/少占 0.5 个人力 ≈ **3-5 万/年**；
- 专家远程问诊把「农户等教授来」变成「当天回复」→ 技术到田时间从周级到小时级；
- 设备告警→任务分派→处置回执闭环，减少巡检人力与事故损失。

**端到端判定：** 底层能力（认证、供应商、模型调用、同步问答、流式 SSE）**均可跑通**；**唯一真正"走不通"的是全新库的首启向导**。对话链路并非"假死"，而是**真实慢模型 + 串行两跳（路由→检索→回答）+ 60s 硬超时**导致的间歇性超时失败（快时 53s 成功、慢时 >60s 报错）。界面会忠实渲染步骤并显示失败，不静默丢消息。

### 1.1 回归定位：为什么"以前能跑、现在走不通"

结论：**这不是 v3.72 的代码回归，而是"环境/模型差异"把两个一直存在的隐患暴露了出来。** 证据如下：

1. **首启向导：不是"以前能用、现在坏了"，而是"从来没接上过、以前根本没被触发"。**
   - `git log -p` 证明：`SetupWizard.vue` 自 v3.69（`e78bbdf`）引入至今，**历史里从未出现 `setupApi.initialize` 调用**；`api/setup.ts` 里该方法存在且返回 token，但无人调用。
   - 你的正常环境（运行中的 **8000**）实测 `GET /setup/status = {"initialized": true}`——**它早已被初始化/播种过**，所以前端守卫直接把用户送到 `/login`，**从不进入向导**，于是"一直是好的"。
   - 只有在**全新数据库/全新机器**（本次隔离副本库）上，用户才会第一次、也是唯一一次走进这个向导，从而撞上"填了等于白填 + 登录回跳死循环"。
2. **对话：不是"以前好、现在坏"，而是"以前用快模型/模拟，现在换成了慢的真实模型"。**
   - 正常 dev 栈默认 `LLM_PROVIDER=fake`（内置 mock，见 `core/config.py:47`，`llm/service.py:30`），**毫秒级返回**，永远不会触发超时。
   - 本次接入真实 `agnes-3.0-flash` 后，单次 `chat/completions` 实测在 **13s–60s+** 波动；而应用对单次模型调用设了 **`llm_timeout_seconds = 60`**（`core/config.py:74`），超时即抛 `模型请求超时（60 秒），请稍后重试。`（`providers_openai.py:116-125`）。
   - 且整条链路是**串行多跳**：先做"智能分类选助手"（≈13s），再做"知识库检索"，最后才"生成回答"；三段时间叠加后经常逼近甚至越过 60s。直连 SSE 那次总耗时 53.2s（险过），浏览器那次答案调用越线即失败。
   - **A/B 已确证**：把 `LLM_TIMEOUT_SECONDS` 调到 180 后，**同一浏览器 prompt 28s 成功返回"正常。"**（`agnes-3.0-flash`，输入 5942 tokens / 11237ms）。即 60s 超时就是那次失败的直接原因，模型与链路本身可用。
3. **附带确认**：v3.72 相对 v3.71 仅改了 `auth.ts(+8)` 与 `chat.ts(+88/-4)`，均为"退出清理 F1 / 断流去重 F4"，**与流式投递、向导提交无关**；`chat/stream.py`、`providers_openai.py` 在 v3.72 未改动。因此不存在"最近改坏了"的代码回归。

> 一句话给决策者：**向导是老账（从没写过 submit），对话是"换真模型后 60s 超时不够用"。** 前者必须补，后者调超时 + 上真流式 + 减跳数即可。

## 2. 维度一 · 资深开发工程师视角

### 2.1 阻断级（🔴 P0）

1. **首启向导完全不落库，且把新用户困在死循环（真 P0）。**
   - `frontend/src/views/SetupWizard.vue:406-420` 的 `next()` 只做校验与 `cur.value++`；`goLogin()`（:426-428）只 `router.push('/login')`。文件注释（:320）声称"完成后调 `/setup/initialize`"，但 `setupApi.initialize`（`frontend/src/api/setup.ts:36-45`）**全仓零调用**。
   - `frontend/src/router/index.ts:260-266` 守卫：任意非 `/setup` 路径在 `initialized=false` 时强制跳回 `/setup`；`stores/auth.ts` 的 `ensureSetupStatus()` 缓存该结果。于是"进入系统→/login→守卫→/setup"形成**不可退出循环**。
   - 后果：院内服务器版/云端版**首次部署无法通过 UI 建出第一个管理员**，只能直接打后端 `POST /setup/initialize` 或走桌面 bootstrap。
   - 修复：第 6 步组装 `SetupInitializePayload` 调 `setupApi.initialize()`，成功后持久化 token 并 `router.replace('/')`；把 `submitting` 真正用于 loading（当前 `:296` 绑定却从不置真）；失败要显式报错而非"伪装完成"。

### 2.2 高（🟠 P1）

2. **模型/供应商出口未统一 `trust_env=False`，特定环境直接硬崩。**
   - 复现：`NO_PROXY` 含 `[::1]` 时，`httpx.AsyncClient()` 解析代理链抛 `InvalidURL: Invalid port ':1]'`。
   - `backend/app/modules/llm/supplier_service.py:652`、`providers_openai.py:118`（**主对话出口**）、`images.py:195`、`video.py:244/379`、`chat/multimodal.py:93` 均默认 `trust_env=True`。
   - 反观较新模块已正确规避：`search/providers.py:42`、`search/egress.py:236`、`cluster/service.py:202`、`tools/custom_runtime.py:102` 都显式 `trust_env=False`。**同仓库标准不统一**。
   - 修复：所有面向上游模型的出口统一 `trust_env=False`，并对 `NO_PROXY` 的 IPv6 括号做容错；补"`NO_PROXY` 含 `[::1]` 时探测仍 200"的回归用例。

3. **对话超时与真实模型能力不匹配（P1 主因）**：`llm_timeout_seconds=60`（`core/config.py:74`）对 `agnes-3.0-flash` 这类慢推理模型偏紧；叠加"分类→检索→回答"串行多跳，极易越线。`providers_openai.py:116-125` 超时直接失败，**没有 token 级流式、没有"先给简答再补检索"的降级**。

4. **模型状态展示与实际调用不一致，误导运维。**
   - `llm/service.py:30` 在 `llm_provider=="fake"` 时直接判定 Mock；真实调用却走 binding 解析链（实测日志"选择了模型提供方 supplier:agnes-main"）。结果"设为当前"后页面顶部仍写"演示/Mock、没有可用供应商"。

5. **异步路径里混入同步阻塞与会话锁。**
   - 129 个 `async def` 注入同步 `Session`；`chat/stream.py:_runner` 在事件循环内做同步 commit；`commander/service.py:154/186/195` 在异步调用链里用进程内锁 + `time.sleep`。

6. **首启可并发建双超管。**
   - `setup/service.py:84` 仅"读判 `is_initialized`"，无唯一闸/无锁；`setup/router.py:48` 匿名且无限流。

### 2.3 中（P2）

7. **巨石与横切重复**：`commander/service.py`(2752)、`chat/service.py`(2162)、`llm/supplier_service.py`(2043)、`library/service.py`(2024)、`agents/declarative.py`(1837)；邮箱脱敏两套（`insights/service.py:105` vs `yards/member_service.py:61`）；`mask_url` 重复（`mcp/service.py:36`、`push/service.py:84`）；时间处理 34 处各写（`core/timezone.py` 已存在）；权限守卫四份（`core/deps.py:102`、`yards/router.py:38`、`quota/router.py:35/47`、`branding/router.py:56`）。
8. **契约/DTO/错误码**：83 处 `response_model=None`；`core/errors.py:10` 错误码为自由字符串，约 200 个字面量无枚举。
9. **可观测性**：`/metrics` 默认关闭且进程内计数（多 worker 失真），无分布式追踪。
10. **测试盲区**：仓库内**无任何 audit 测试**（`find tests -name "*audit*"` 为空）；无"慢模型超时""首启并发""NO_PROXY IPv6"回归用例。

### 2.4 运行效率

- **单句回答 31–53s，且会 60s 超时**：同步实测 31s；直连 SSE 实测 53s；浏览器流式在答案调用 >60s 时直接失败。根因是"两跳模型 + 知识库检索 + 60s 硬超时"，而非代码阻塞。

## 4. 维度三 · 重度用户视角（生产力工具标准）

1. **"顺手程度"不达标（🟠）**：一条一句话确认，同步 31s、直连流式 53s、浏览器流式还在 60s 处超时失败。重度用户每天几十次交互，这个延迟与不稳定性无法形成依赖。
2. **可挽回性差（🟠）**：长等待/失败缺"停止生成/重试/换模型"就地入口；我实际只能刷新，且 60s 超时会落库一条 `failed` 记录。建议加"取消/重试/改用快速模型"。
3. **工具链脆弱（🟠）**：联网搜索命中 429 无"降级为不搜索直接答"的兜底。
4. **价值产出可期（🟢/🟠）**：能力面很宽（文档/PPT/图像/视频/知识库/诊断/工单/台账/班组/自生长），主链路稳定后有"一句话到成品"的潜力；目前"潜力"大于"当下可用"。
5. **信任成本（🟠）**：无 token 级流式，用户看不到"模型在写"，长等待焦虑被放大（虽有步骤条，但静态）。

## 5. 维度四 · 小白用户视角（首触 → 是否给第二次机会）

1. **首次上手中断（🔴 阻断）**：全新部署时认真填完 6 步，系统显示"配置已写入系统"，点"进入系统"却被弹回向导——**没有账号被创建**。
2. **登录后退回（🔴 阻断）**：即便通过后端建号登录，未初始化判定仍会把用户推回 `/setup`。
3. **口令规则不一致（🟡）**：注册页"6 位"（`SignupView.vue:69`）而向导"至少 10 位"（`SetupWizard.vue:419`）。
4. **会不会给第二次机会（判断）**：**若首启在全新机器上必挂，大概率不会。** 首启是唯一"第一印象窗口"，失败且伪装成功最伤信任。修好向导 + 让"三步上手"（`FirstRunGuide` 目前只在 `Dashboard.vue:21`）覆盖更多页，留存仍有救。

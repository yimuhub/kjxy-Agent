# 实际痛点解决方案（2026-11-03）

> 依据：全库逐行审查 + 对现有能力的盘点。原则：**每一条都优先复用已验证的基础设施**，
> 给出工作量与依赖，按「感知收益 / 成本」排序。

## 痛点一：生成的东西「好不好」没人知道——把已有的评测门禁接进生成链路

**现状**：技能模板强制带 `eval_cases`（≥2 条），`evolution` 已有完整评测框架与发布门禁
（`EVAL_GATE_BLOCKED`），但**一句话生成的草稿从不自动跑评测**，审核者只能凭肉眼判断。

**方案**：生成落草稿时同步跑一遍该技能的 eval_cases（已有 `answer_fn` 基建），
把通过率写进 `blueprint_json`/卡片，专家审核队列直接显示「自动评测 2/2 通过」。
- 成本：后端 ~半天（评测调用已有）；生成耗时 +5~10s（可后台跑）。
- 收益：审核从「读作文」变「看分数」，垃圾草稿在审核前就被拦住。

## 痛点二：负责人「看不到」平台发生了什么——把已有的报告接进已有的推送

**现状**：指挥官周报/月度迭代、自我总结运行报告都在生成，但**只躺在页面里等人来看**；
另一头，企微/钉钉/飞书推送通道、事件订阅框架（`push.dispatch`，永不影响主流程）已全部就绪。

**方案**：新增 `weekly_report` 推送事件：指挥官周报落地时自动 dispatch（标题 + 3 行摘要 +
平台链接），负责人在群里点开即读。自我总结的运行结果同理。
- 成本：~2 小时（两端都是现成的，只加一个事件类型 + 一处 dispatch 调用）。
- 收益：负责人零成本感知平台健康度；这是「把已生成的价值送达」的最短路径。

## 痛点三：新小院冷启动即「智能体无米之炊」

**现状**：新装小院知识库为空 → 生成/回答质量必然差，用户第一印象受损。
市场里已有 12 个内置技能种子（`ensure_builtin_skills`），但知识侧没有种子。

**方案**：做一个「农技知识种子包」——整理公开农技 FAQ（病虫害识别/水肥/农时，
数百条即可）作为内置知识文档随 `seed` 导入（`import_skill_file` 同款导入闸已就绪），
新小院开通时自动挂载，标记 `source=builtin` 可整包卸载。
- 成本：内容整理 1~2 天 + 导入脚本半天。
- 收益：开箱即可获得有依据的回答，第一印象决定留存。

## 痛点四：田间场景入口太深

**现状**：bots 网关已支持企微/钉钉/飞书与 `/use` 切换，但常用能力仍需进网页点菜单。

**方案**：为高频技能注册快捷命令（`/病虫害 <描述>`、`/配肥 <作物>`），映射到
skill 检索→直接执行→返回带引用的结果。技能 definition 里已有 `when_to_use`
关键词，命令路由可直接复用 `skill_agent` 的检索打分。
- 成本：1 天（网关命令解析已有 `/use` 前例）。
- 收益：把「打开网页→找技能→填参数」压缩成一条消息，田间场景价值最大。

## 痛点五：给上级交材料要手工整理

**现状**：文档生成模块（Word/Excel/PPT/PDF）与指挥官月度迭代报告都已存在，但两条链路没接。

**方案**：月度迭代报告页加「导出 Word」——直接调文档生成管线渲染 `report_md`，
带平台抬头与小院名。
- 成本：~半天。
- 收益：管理员向政府/公司交月报从手工整理变一键导出；对科技小院（对上汇报频繁）是高频刚需。

## 痛点六：搜索源受制于反爬（工程侧收尾）

**现状**：必应已稳定；搜狗/360 反爬无法纯 HTTP 通过。provider 抽象已就绪。

**方案**（二选一，按客户部署形态）：
- 桌面/服务器版：`compose` 加 SearXNG 可选服务 + 设置页「一键启用本地 SearXNG」
  （方案文档 v3.1 就预留了该备选，provider 无需改）；
- 公网版：推荐客户配一个 Tavily Key（免费档 1000 次/月），设置页已有入口。

## 工程效率备忘（本轮审查结论，均不构成阻塞）
